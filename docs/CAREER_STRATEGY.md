|------|-----------------|

### What Actually Gets You Hired
1. **Quantified impact** - "Reduced false positives by 30%" not "wrote detection rules"
2. **Framework alignment** - MITRE ATT&CK, NIST, OWASP mapping in projects
3. **4-5 deep projects beat 50 shallow ones** - depth over breadth
4. **Custom tooling** - shows you don't just use tools, you build them
5. **Business risk translation** - can you explain findings to a CISO?

### What Kills Your Chances
- Repos named "project1", "test", "misc"
- Missing READMEs or documentation
- No commit activity for months
- 30 tools listed with no context on how you used them
- No quantified impact anywhere

## PRODUCTION-GRADE vs HOBBY PROJECT (The Gap)

| Dimension | Hobby/Student | Production-Grade |
|-----------|---------------|-----------------|
| **Architecture** | Single script, flat directory | Modular layers with interfaces, plugin system |
| **Extensibility** | Fork to customize | Plugin architecture (YAML templates, RPC, entry points) |
| **Testing** | None or manual | Unit, integration, fuzzing, benchmarks against known-vulnerable targets |
| **CI/CD** | None | SAST, SCA, container scanning, signed releases, Dependabot |
| **Output** | Console text only | CEF, LEEF, JSON, syslog, SIEM webhooks |
| **Dashboard** | Basic HTML table | Role-based, real-time streaming, MTTA/MTTR metrics, dark mode |
| **Docs** | Sparse README | ADRs, threat model, API specs, SECURITY.md, CONTRIBUTING.md, OpenSSF badge |
| **Install** | Clone + pip install + pray | `go install`, single binary, Docker image, `brew install` |
| **Error handling** | Crashes | Circuit breakers, graceful degradation, per-target error tracking |
| **Config** | Hardcoded values | Secure defaults, env-aware, YAML/TOML config, secrets management |

### Every Project Must Have
- [ ] Professional README with terminal demo GIF
- [ ] One-command install (single binary or Docker)
- [ ] Badge row (build status, coverage, license, Docker pulls)
- [ ] Architecture diagram
- [ ] SECURITY.md (vulnerability disclosure process)
- [ ] CONTRIBUTING.md
- [ ] CHANGELOG.md (Keep a Changelog format)
- [ ] Automated CI with tests
- [ ] Multiple output formats (JSON, CSV, SARIF at minimum)
- [ ] MITRE ATT&CK / OWASP / NIST framework mapping where applicable
